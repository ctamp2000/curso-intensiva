# UTInaREAL — Instruções para IA

## Sobre o projeto

O **UTInaREAL** é um site voltado para médicos intensivistas e outros profissionais que desejam aprofundar seus conhecimentos em medicina intensiva.

O site reúne:

- conteúdos práticos;
- casos clínicos;
- materiais exclusivos;
- conteúdos voltados à tomada de decisão na UTI.

O objetivo principal do UTInaREAL é ajudar médicos intensivistas a desenvolverem uma tomada de decisão mais segura na prática da terapia intensiva.

## Tecnologias utilizadas

O projeto utiliza:

- React
- Tailwind CSS
- Vite

O código-fonte é versionado no GitHub.

## Estrutura atual do projeto

A estrutura principal está organizada da seguinte forma:

- `src/assets/` — arquivos e recursos visuais do projeto.
- `src/components/layout/` — componentes estruturais, como `Header.jsx` e `Footer.jsx`.
- `src/components/sections/` — seções das páginas, como `HeroSection.jsx` e `FeaturedProjects.jsx`.
- `src/components/ui/` — componentes reutilizáveis de interface, como `ProjectCard.jsx`.
- `src/components/Home.jsx` — conteúdo/componente relacionado à página inicial.
- `src/components/Collaborators.jsx` — conteúdo relacionado aos colaboradores.
- `src/components/Products.jsx` — conteúdo relacionado aos produtos.
- `src/data/projects.js` — dados utilizados pelos projetos apresentados no site.

## Como a IA deve trabalhar neste projeto

Ao ajudar no desenvolvimento do UTInaREAL:

1. Antes de propor qualquer alteração, explique o que pretende fazer.
2. Faça uma alteração de cada vez.
3. Informe exatamente qual arquivo deverá ser alterado.
4. Sempre que possível, indique também a parte do arquivo onde a alteração será feita.
5. Evite modificar código que já está funcionando corretamente.
6. Não faça refatorações desnecessárias.
7. Não altere nomes de componentes, arquivos, funções ou variáveis sem necessidade.
8. Preserve a estrutura atual do projeto sempre que possível.
9. Depois da alteração, explique o que foi feito e por que foi feito.
10. Prefira soluções simples e fáceis de manter.
11. Não instale novas bibliotecas sem antes explicar por que elas são necessárias.
12. Quando houver mais de uma solução possível, apresente primeiro a mais simples.
13. Não faça várias alterações simultaneamente sem necessidade.
14. Se uma alteração puder afetar outras partes do site, avise antes.

## Quando houver um problema no código

Ao analisar um erro ou comportamento inesperado:

1. Identifique primeiro a provável causa.
2. Explique o problema em linguagem clara.
3. Informe qual arquivo precisa ser alterado.
4. Mostre a menor alteração necessária para corrigir o problema.
5. Explique por que a correção funciona.
6. Evite substituir arquivos inteiros quando apenas algumas linhas precisam ser modificadas.

## Forma de explicar

As explicações devem ser claras e didáticas.

Evite respostas excessivamente técnicas quando uma explicação simples for suficiente.

Quando apresentar código:

- deixe claro o que deve ser substituído;
- indique onde inserir o novo código;
- diferencie código novo de código existente;
- não omita etapas necessárias para realizar a alteração.

## Princípio geral

No UTInaREAL, a prioridade é:

**entender primeiro, alterar depois.**

Sempre preservar o que já funciona e fazer mudanças pequenas, controladas e compreensíveis.
